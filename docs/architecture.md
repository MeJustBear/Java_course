# Логика работы приложения

«Online schedule» — веб-приложение с расписанием занятий и оценками.
Три роли: студент, преподаватель, администратор.

## 1. Архитектура исходного проекта (Java)

```
Браузер (HTML / JSP / JS)
        │
Servlets (LoginServlet, MainServlet, LogoutServlet)
        │
DBConnector (singleton-фасад ≈ сервисный слой)
        │
myDataBase (in-memory хранилище ≈ репозиторий)
        │
TXT / XML файлы на диске
```

- **LoginServlet** (`/schedule/login/*`) — вход: проверяет пару логин/пароль,
  кладёт логин в `HttpSession` и cookie `name`.
- **MainServlet** (`/schedule/*`) — вся логика: по префиксу логина определяет роль
  и рендерит HTML прямо в `PrintWriter` (для админа — редирект на JSP).
- **LogoutServlet** (`/schedule/logout/*`) — инвалидация сессии и очистка cookie.
- Сохранение данных на диск происходило только в `MainServlet.destroy()`.

## 2. Сценарии по ролям

### Студент (`st*`)
- Видит расписание своей группы: по каждому предмету — преподаватель,
  список занятий с датами, свои оценки и комментарии.
- Может открыть график оценок по предмету (`/schedule/graphic/{groupId}/`).

### Преподаватель (`te*`)
- Главная — список своих предметов и групп, где он их ведёт.
- `/schedule/gr{N}/{Subject}/` — занятия предмета в группе;
  может **добавить** занятие (название + дата) и **удалить** занятие.
- `/schedule/gr{N}/{Subject}/{Lesson}/` — журнал занятия;
  может **выставить оценку** (2–5) и комментарий любому студенту группы.
- При создании занятия каждому студенту группы создаётся пустой результат
  (mark = 0 — «не выставлена»).

### Администратор (`ad*`)
- Главная — список групп (с численностью) и преподавателей (с предметами).
- Группы: добавить (`/schedule/add_group/`), удалить (`/schedule/remove_group/`).
  При удалении группы удаляются её студенты и все назначения предметов.
- Студенты: в карточке группы (`/schedule/find_group/{id}`) — добавить
  (`gr{N}/add_student`) и удалить (`gr{N}/remove_student`).
  При добавлении генерируется логин (`st{next}`) и случайный пароль из 4 символов,
  которые показываются администратору один раз; студент добавляется во все
  существующие занятия группы с пустым результатом.
- Преподаватели: добавить (`/schedule/add_teacher/`, логин `te{next}` + пароль),
  удалить (`/schedule/remove_teacher/`, вместе с его назначениями).
- Предметы: назначить предмет преподавателю на группу (`/schedule/add_subject/`;
  если предмет в группе уже был у другого преподавателя — назначение
  переходит новому), снять предмет (`/schedule/remove_subject/`).
- Имена/фамилии и названия предметов валидируются (только буквы).

## 3. Аутентификация

- Форма логина → `POST /schedule/login/` (`uname`, `psw`).
- Успех: логин сохраняется в сессии и cookie; неуспех: редирект обратно на форму.
- Все страницы `/schedule/*` без сессии редиректят на форму логина.
- Роль определяется префиксом логина, «чужие» страницы недоступны.

## 4. Архитектура Kotlin-версии

Слои и сценарии сохранены, инфраструктура заменена на современный стек:

```
Браузер (Thymeleaf-шаблоны, тот же CSS/JS)
        │
Controllers (Spring MVC): Login/Logout, Student, Teacher, Admin
        │
Services: AuthService, ScheduleService, AdminService
        │
Spring Data JPA repositories (Hibernate ORM)
        │
PostgreSQL (prod / docker-compose)  |  H2 (тесты)
        │
Redis (кеш расписаний, spring-cache)
```

Соответствие компонентов:

| Java                          | Kotlin                                      |
|-------------------------------|---------------------------------------------|
| `LoginServlet`/`LogoutServlet`| `AuthController` + `AuthService`            |
| `MainServlet` (student/teacher ветки) | `StudentController`, `TeacherController` + `ScheduleService` |
| `MainServlet` (admin ветка) + JSP | `AdminController` + `AdminService` + Thymeleaf |
| `DBConnector`                 | сервисный слой (Spring beans)               |
| `myDataBase` + файлы          | JPA-репозитории + PostgreSQL                |
| `parser` (XML)                | не нужен: данные в БД, сид — `DataSeeder`   |
| генерация HTML в `PrintWriter`| Thymeleaf-шаблоны                           |
| Cookie + `HttpSession`        | `HttpSession` (Spring Session-совместимо)   |
| сохранение в `destroy()`      | транзакции Hibernate — запись сразу         |

Отличия/улучшения при сохранении поведения:

- Оценки и структура данных хранятся в PostgreSQL через Hibernate (ORM),
  вместо ручного парсинга XML/TXT.
- Расписание студента и список предметов преподавателя кешируются в Redis
  (`@Cacheable`), кеш инвалидируется при изменениях (`@CacheEvict`).
- Роль хранится в БД (дискриминатор), но логины сохраняют исходные префиксы.
- URL-схема повторяет исходную (`/schedule/…`), поэтому сценарии из раздела 2
  работают так же.
